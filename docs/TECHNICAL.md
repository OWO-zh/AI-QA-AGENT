# 工具协同 Agent 系统 技术设计文档

## 1. 项目概述
### 1.1 项目背景
企业内部信息分散在文档库、业务数据库、外部资讯平台等多个系统，员工获取完整信息需跨平台操作，效率低且易遗漏；通用大模型虽具备推理能力，但无法直接访问私有数据、存在幻觉问题，且直接对接内部数据存在安全风险。

### 1.2 建设目标
构建一个可自主决策信息来源、协同调度多类工具、整合分散信息输出统一回答的智能 Agent 系统，实现：
- 一个入口覆盖内部文档、业务数据、外部资讯三类信息
- 回答可溯源、可解释，降低大模型幻觉影响
- 数据安全隔离，敏感信息不流出企业内网
- 高可用容错设计，减少系统静默失效

### 1.3 核心验收指标
- 工具调用准确率 ≥ 90%
- 知识范围内回答准确率 ≥ 90%
- 系统静默失败率 ≤ 1%
- 支持知识库文件热更新与新工具快速扩展

## 2. 整体架构设计
### 2.1 架构总览
系统采用分层设计，自下而上分为：基础资源层、工具能力层、Agent 调度层、交互展示层。
- **基础资源层**：大模型服务（qwen-plus）、向量数据库（FAISS）、业务数据库（SQLite）、搜索 API（Tavily）
- **工具能力层**：将各类能力封装为标准 Function Calling 工具，统一输入输出格式
- **Agent 调度层**：基于 LangGraph 实现状态机调度，负责意图决策、工具执行、结果生成
- **交互展示层**：Streamlit 可视化界面，负责用户交互、状态展示、结果呈现

### 2.2 状态机工作流设计
基于 LangGraph 构建三节点有状态工作流，支持条件分支与状态持久化：
1. **决策节点（Decide Node）**
   - 输入：用户问题 + 对话上下文
   - 能力：意图识别、工具选择、参数提取
   - 分支：无需工具直接回答 / 调用单工具 / 调用多工具并行执行
2. **工具执行节点（Tools Execute Node）**
   - 输入：决策节点输出的工具列表与参数
   - 能力：依次执行工具（当前为串行，后续可扩展为并行）、异常捕获、自动重试、全局异常保护
   - 输出：结构化的工具返回结果（含工具名称 `name` 字段）
3. **答案生成节点（Answer Node）**
   - 输入：原始问题 + 工具返回结果集合
   - 能力：信息整合、溯源标注、答案生成，含空答案兜底与 `tool_calls` 输出过滤
   - 输出：带来源标注的最终回答

### 2.3 数据流走向
用户提问 → 会话上下文注入 → 意图决策 → 工具路由 → 工具执行（含容错重试）→ 结果聚合 → 答案生成 → 返回前端展示

## 3. 核心模块详细设计
### 3.1 决策节点
- 实现方式：通过系统 Prompt 强制规则 + Function Calling 自动选择工具，模型返回结构化 `tool_calls`。
- 路由规则：
    - 问题涉及内部文档 / 制度 → 路由至知识库检索工具
    - 问题涉及业务数据统计 / 查询 → 路由至数据库查询工具
    - 问题涉及实时资讯 / 外部信息 → 路由至联网搜索工具
    - 复杂问题同时涉及多类信息 → 调度多个工具依次执行
- 优化手段：
    - 强制规则：若用户问题中包含“文档”“PDF”“文件”等字样，必须优先调用 `search_knowledge_base`。
    - SQL 错误重试时，将上一次的错误信息注入系统提示，引导模型修正 SQL。

### 3.2 工具执行模块
#### 3.2.1 RAG 知识库检索工具
- **分块策略**：采用带重叠的递归字符分块（chunk_size=500, overlap=100），中文友好分隔符。
- **向量存储**：基于 FAISS 构建本地向量索引，支持增量更新。Embedding 模型采用 `shibing624/text2vec-base-chinese`，懒加载避免启动阻塞。
- **检索机制**：
    - 采用**混合检索**：向量语义检索 + BM25 关键词检索双路召回，合并去重后通过 BGE-Reranker 精排取 Top-K。
    - **来源多样性优化**：多文档场景下，优先保证不同文档（根据 `source` 字段区分）至少有一个片段入选，避免检索偏置导致答案片面。
- **拒答设计**：若所有候选片段的相关性过低或检索为空，则明确告知用户未找到相关内容。
- **可追溯性**：返回结果中标注片段来源文档名，便于溯源。

#### 3.2.2 数据库查询工具
- **生成逻辑**：大模型根据表结构 Schema（`employees` 表）自动生成 SQL 查询语句。
- **安全校验**：
    - SQL 白名单校验：正则确保仅允许 `SELECT` 查询，禁止 `DROP`/`DELETE`/`UPDATE` 等危险关键字。
    - 表名白名单：仅允许访问 `employees`、`departments`、`salary` 表。
    - 数据库连接使用**绝对路径**（`os.path.join(os.path.dirname(__file__), 'company.db')`），避免工作目录变化导致连接失败。
- **自纠错机制**：SQL 执行报错时，将错误信息通过系统提示回传给决策节点，模型自动修正后重试，最多重试 2 次。

#### 3.2.3 联网搜索工具
- 基于 Tavily Search API 实现实时资讯检索。
- 返回结果包含标题、摘要、来源链接，确保信息可追溯。
- **关键词自动扩展**：首次检索结果不足 2 条时，自动提取前三个词作为新关键词进行二次检索，提升召回率。

#### 3.3 答案生成节点
- 统一整合多工具返回的结构化结果，按信息来源分段落组织答案。
- 强制标注每条信息的来源（文档片段 / 数据库数据 / 搜索来源）。
- 约束模型仅基于检索结果作答，无对应信息时主动说明，不编造内容。
- **容错增强**：
    - 若模型返回空内容，自动替换为友好提示：“抱歉，系统暂时无法整合信息，请稍后重试或换一种问法。”
    - 若模型错误地输出 `tool_calls` 而非自然语言，前端自动过滤并提示用户简化提问。
- **性能优化**：系统提示中限制回答不超过 3 句话、150 字，减少生成耗时。

## 4. 工程化与可靠性设计
### 4.1 安全防护体系
- **数据安全**：数据库查询与联网搜索物理隔离，内部数据不传递给外部 API。
- **SQL 安全**：正则语法校验 + 表名白名单 + 绝对路径连接，确保仅允许安全的只读操作。
- **文件安全**：上传文件仅允许 PDF/TXT 格式；路径穿越校验、后缀白名单、单文件 ≤10MB、单次最多 5 个、临时文件用完即删。
- **会话隔离**：基于 Streamlit Session State 实现用户级数据隔离，知识库与对话记录互不干扰。
- **配置安全**：`config.yaml` 包含 API 密钥，已加入 `.gitignore`，仓库中仅提供 `config.yaml.example` 模板。

### 4.2 三级容错降级机制
1. **一级容错**：工具调用失败自动重试（最多 2 次），适配网络波动与接口限流。
2. **二级容错**：检索结果为空时，自动扩展关键词 / 放宽匹配条件二次检索。
3. **三级容错**：所有工具均无有效结果时，主动告知用户并给出查询建议，杜绝静默失败。
4. **全局异常保护**：工具执行节点增加 `try/except` 包裹整个循环，即使个别工具崩溃，也能返回部分结果并记录日志，避免整个工作流卡死。

### 4.3 全链路日志系统
- 分级日志输出：INFO/DEBUG/WARNING/ERROR 四级。
- 全链路埋点：记录每轮对话的意图决策、工具调用、执行耗时、返回结果。
- 日志持久化：本地文件 `agent_run.log` 存储，支持问题回溯与效果调优。
- **错误透明化**：工具异常时，前端展示具体异常类型和消息，终端打印完整堆栈，便于定位。

### 4.4 会话状态管理
- 基于 Streamlit Session State 实现会话级状态存储。
- 对话历史、知识库实例、工具状态均与会话绑定。
- 每次新问题前自动重置瞬时状态（`retry_count`、`has_sql_error`），避免跨轮污染。
- 支持手动清空对话，重置会话状态。

## 5. 性能与效果验证
### 5.1 测试数据集
采用 **20 条人工设计的典型验证用例**，覆盖以下场景：
- **单工具查询**：知识库概括、数据库单值/聚合/排序、搜索实时信息与自动重试。
- **多工具混合**：数据库 + 搜索、知识库 + 搜索、三工具联动。
- **边界与容错**：SQL 自纠错、拒答、文件未上传、内容安全拦截。

所有用例均通过逐条手动执行，确保功能正确性。完整用例列表及预期结果详见项目文档 `test_cases.md`。

## 6. 扩展开发指南
新增工具仅需三步：
1. 在 `agent.py` 的 `TOOLS` 列表中补充 Function Calling 描述与参数 Schema。
2. 在 `tool_execute_node` 中添加 `if/elif` 分支，调用具体工具函数。
3. 若涉及安全策略（如新数据库表），更新白名单配置。

项目还预留了以下扩展点：
- **RAG 增强**：可启用已集成的 BM25 混合检索和 Reranker，当前已默认开启。
- **工具并行化**：将 `tool_execute_node` 中的串行执行改为 `asyncio` 并行，减少多工具调用延迟。
- **模型切换**：通过 `config.yaml` 注入模型名，支持零代码切换 `qwen-plus`/`qwen-turbo` 等。
- **生产化部署**：增加用户认证、Redis 会话持久化、API 限流等。

## 7. 部署说明
- **本地开发**：执行 `pip install -r requirements.txt`，创建 `config.yaml`（参考 `config.yaml.example`），运行 `python init_db.py` 初始化数据库，最后 `streamlit run app.py` 启动。
- **容器化部署**：可编写 Dockerfile 基于 `python:3.10-slim` 构建镜像，将模型文件挂载为卷以加速启动。
- **生产建议**：接入 Redis 持久化会话、增加用户认证、配置接口限流、将 SQLite 替换为 PostgreSQL 等企业级数据库。
